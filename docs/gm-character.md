# Native character, health and exploration operations

Staged implementation only: exact Foundry 14.368 and dnd5e 6.0.3. No live gameplay, user permission changes, or deployment has been performed by this feature worker.

`foundry_gm_character_state` and `foundry_gm_character_apply` are actual REST/MCP descriptors (`POST /gm/character/state`, `POST /gm/character/apply`) backed by native bridge commands `gmCharacterRead` and `gmCharacterApply`. Lookup the recipe catalog first. Both require the exact opted-in authenticated active native GM, world and active rendered scene. The supplied actor ID is optional confirmation of the token's actual synthetic/linked actor; a world Actor ID cannot bypass token scope.

Inputs share `{schemaVersion:"gm-actions-v1",worldId,userId,sceneId,action}`. Apply adds the complete state returned by read as `expectedState`, plus bounded `idempotencyKey` and `correlationId`. Native expected-state comparison, durable private journal reservations and scoped result receipts are shared with combat/activity operations. An unfinished reservation, missing post-dispatch proof, changed connection, lost acknowledgement, or uncertain result blocks further new intents. A retry with the same complete original request returns the existing receipt without another roll/spend. Never regenerate expected state and reuse an existing key.

Native damage, death/concentration saves, rest and effect behavior was inspected in installed `dnd5e.mjs` at lines 43218-43400, 43738-43850, 44104-44246, 44424, 44637-44863, 46019-46053. Edition is read from native `dnd5e.settings.rulesVersion`; ambiguous 2014/2024 interpretations are explicit rulings. `CurrencyManager.transferCurrency` delegates to an unawaited native award call (75843); reliable atomic transfer is not claimed.

The supplemental `stable` native status exists at `dnd5e.mjs:54157-54159` and is merged into `CONFIG.statusEffects` at `96305-96324`; Foundry core `client/documents/actor.mjs:547-577` creates/removes actual durable ActiveEffects through `toggleStatusEffect`. Native stable death-save outcomes reset successes/failures to zero at `dnd5e.mjs:8587-8613`. Native `rollDeathSave:44110` does not consult the stable status, so the wrapper must refuse it explicitly. Native `updateDowned:46085-46117` respects world automation settings and handles dead/unconscious, not stable removal. The tool makes no claim that the native sheet automatically suppresses death saves or clears stable after damage. Failed partial stabilization retains an uncertain reservation and never replays the counter reset/effects.

Additional wrapper evidence: equippable `attuned` native Boolean schema `dnd5e.mjs:29223` and native sheet update `76586`; native actor XP updates `31607`; signed `hp.tempmax` field `7915-7917` and native HP derivation `8304-8309`; native Item deletion `21581`. Native sheet item moves create target items and then issue a separate unawaited source deletion at `66157-66227`, confirming that transfer is a multiple-document workflow rather than a proven atomic operation. The exposed copy/quantity/remove steps now permit a fully MCP-driven explicit transfer recipe with honest partial-failure recovery.

Exploration recipes compose these operations: skill/tool checks, native passive score reads, explicit targets and typed trap damage. Group/contested checks perform ordered native checks with distinct receipt keys, then an explicit comparison/pass/tie policy; this module invents no group threshold. Stealth/perception/detection do not reveal hidden tokens solely because a check succeeded. Traps/disarm, grapple/shove, travel encounters and improvised actions require a scoped GM ruling before the generic door/light/movement/world-time primitives. Existing MCP document/effect/scene/token operations remain available; no parallel terrain or movement engine is introduced here.
