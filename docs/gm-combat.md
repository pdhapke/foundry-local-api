# Native GM combat tools

Staged source for Foundry 14.368 / dnd5e 6.0.3. The authenticated active native GM, current world and current rendered active scene are required. No ownership changes, independent accounts, history capture, autonomous event activation or installed-world writes are performed by source installation.

`foundry_gm_combat_state` and `foundry_gm_combat_apply` are ordinary generic MCP descriptors and REST POST routes `/gm/combat/state` and `/gm/combat/apply`. Codex DM recipes must use these same tools. Input uses `schemaVersion: "gm-actions-v1"`, `worldId`, `userId`, `sceneId`, and `action`. Apply additionally requires the full preceding state result as `expectedState`, a stable `idempotencyKey`, and `correlationId`. Every mutation uses the durable native receipt journal. Confirmed receipt returns native state in `after`; an uncertain receipt requires document reconciliation and must never be replayed with a new key.

The ledger lives in a separately created default-NONE JournalEntry. Existing non-GM permissions, ambiguous ledgers, malformed budgets and capacity limits fail closed. Ledger writes verify exact persisted readback; no-op updates become uncertain. Native receipt journals separately reserve dispatches and protect retry/reconnect/restart against duplicate rolls/spends. Budgets never reset from wall clock. MCP-controlled next/start reset only the next initialized combatant's ordinary budgets from actual native movement speed; reactions refresh on that participant's own turn. Ready expires before the next own turn. An externally changed combat cursor blocks stale budget actions; reconciling multiple participants after unobserved manual history remains human-required.

Native activity-use integrates `assertCombatActivityBudget` and `spendCombatActivityBudget` under the SAME outer native receipt reservation, before activity execution. Do not separately budget-spend an activity (which would double charge it). Ordinary action/bonus/reaction activation requires the initialized current ledger and sufficient allowance. Pending ready/reaction/opportunity activity binds its reservation key to the interruption; resolution confirms that exact receipt without charging the reaction twice. An already-reserved activity cannot be declined as if it never happened. A failed/uncertain activation does not silently refund the budget; investigate native resources and the durable receipt first. Before movement, explicitly decide whether reach crossing creates an opportunity window, open/resolve that interruption, then commit actual movement with the native movement tool. These tools do not invent an opportunity trigger or execute held activities autonomously. A human-only interruption without an activity binding is an explicit ruling, not proof that an attack happened.

Native scene movement integrates `assertCombatMovementBudget(input, tokenId, amount)` and `spendCombatMovementBudget(input, tokenId, amount)` inside its outer reservation before native verified movement. Cost is a finite explicit native/adjudicated distance in scene units; `action.ruling` records terrain decisions. It requires a synced initialized current-turn budget and matching native actor movement units and scene grid units. Unknown/over-budget costs, mismatched units and pending interruptions refuse before movement. No additional movement arithmetic or silent feet/meters conversion is invented.

Held spells use `foundry_gm_activity_apply` with `mode: "use", phase: "ready", ready: {choiceId, trigger, ruling}`. Casting requires an actual placed actor's one-action native spell, explicit retained `spellSlot`/`scaling`, no targets or immediate attack/damage/template/summon follow-up, and native concentration configuration. The activity wrapper casts once with an ephemeral native item clone retaining the real item/activity IDs and enabling native concentration, then records the exact native effect and original-source provenance under the same action/resource receipt. It does not edit the persistent spell. Open an explicit combat `interrupt-open` of kind `ready` linked to that choice; release the original activity with `phase: "release", release: {readyId, castReceipt}` and the same retained slot/scaling. Release verifies confirmed cast provenance, a maintained exact concentration effect and a unique pending trigger, spends reaction once, and invokes native usage with consumption disabled. Resolve the combat interruption with the release receipt. Do not independently spend budgets or use raw combat `ready` for spells.

For an originally concentrating spell, release replaces the exact temporary effect with the native original-duration concentration effect; a nonconcentrating spell clears only the temporary effect. Expiry/end clears the exact still-maintained temporary effect without refunding the cast. Lost concentration prevents release. An unobserved manual combat transition requires explicit ready expiry before budget reconciliation; expiry does not silently synchronize stale budgets. Native veto or partial failure remains uncertain and must be reconciled rather than recast. Linked activities, templates, summons and ambiguous release effects are refused before consumption or retained as explicit human decisions by the bounded activity tools.

Source evidence is the installed dnd5e 6.0.3 `dnd5e.mjs`: `Activity.use` at 17604 accepts suppression of subsequent actions (17695); `_prepareUsageUpdates` at 17978 returns no resource updates for `consume:false`; native concentration data at 13229 requires embedded item provenance and concentration duration; `Actor.beginConcentrating`/`endConcentration` at 43524/43563 create/remove actual effects. Offline fixtures verify cast provenance, loss, retained configuration, reaction accounting, expiry, replacement, and persisted readback. Real native clone identity and effect creation remain staged browser acceptance.

Native `activity.use` owns legendary/mythic activity resource consumption (`resources.legact`); ledger special-decision never duplicates that resource spending. Lair scheduling, legendary resistance outcomes, Extra Attack counts, 2014/2024 surprise, Dodge/Help effects and improvised legality require the real native feature/effect tools plus explicit GM decisions. A recorded ruling alone is not native rules execution. Unit placement uses generic existing scene/token tools before encounter creation, rather than manufacturing monster stats.

Offline tests use native-shaped documents, private journals and native receipt runtime. Live LAN/browser/multiple-client roll privacy and native rules acceptance remain staged checks; no new deployment or live gameplay has been authorized.
