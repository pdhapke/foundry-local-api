# Token light MCP endpoint worker gate

Implemented only `server/src/endpoints/session-actions.ts` and its focused tests. No runtime actions, mutation, service operation or build performed by this worker.

`foundry_set_token_light` is POST `/session-actions/token/light`, with strict worldId/userId/requestId/correlationId/sceneId/tokenId/light input. The light patch requires finite 0 <= bright <= dim <= 10000 at native 0.01 precision, optional #RRGGBB/null color canonicalized to lowercase and finite alpha in [0,1]. Radius uses scene distance units. Light follows the token natively; vision, fog and walls still determine revealed information. This is MCP/core action plumbing only, with no AI/Python narration scope added.

The dedicated endpoint constructs the existing `core-actions-v1` action with origin `ai-dm`, kind `token.light`, selected scene and token target, then delegates to the existing core handler. It creates no CRUD shortcut, serialization queue, receipt store or retry mechanism. Equivalent dedicated/core requests share world/user/requestId deduplication. Changed arguments and historical connection generations cannot replay.

Authoritative receipt confirmation checks the actual returned `state.light` against every supplied patch field exactly. No decimal rounding or inferred success. Native extra LightData fields are permitted in the receipt so full native state may preserve animation/angle/other fields; native worker validates their preservation. A mismatch produces uncertain and fences the shared routine lane. After native dispatch, the endpoint also checks exact GM client ID, user, GM lane, consent and connection generation before accepting asynchronous acknowledgement. Identity drift yields uncertain and fences subsequent mutations.

Worker verification: **10 focused tests passed** with `node --import tsx --test server/src/endpoints/session-actions.test.ts server/src/endpoints/core-rollout.validation.test.ts`. Cases cover strict schema and broad/numeric/color abuse; disconnected/non-GM/inactive/wrong-world refusal; native failure; dedicated/core simultaneous duplicate delivery; changed request and reconnect replay refusal; light readback mismatch; connection drift during native acknowledgement; and predispatch subprecision rejection plus canonical color dedup. Existing independent core uncertainty fencing also passes.

Independent review found that native LightData radius fields normalize to 0.01 and ColorField emits lowercase. The initial broader schema accepted values that native would legitimately normalize, after which exact receipt comparison would fence the lane. Input precision is now rejected before dispatch, not rounded synthetically; both routes canonicalize color before action fingerprint and native dispatch. AlphaField has no native step and remains precision-preserving. Numeric/color receipt equality remains strict.

Initial server typecheck used stale shared declarations and failed because token.light was absent and optional color/alpha lacked explicit undefined under exactOptionalPropertyTypes. Native/shared worker updated the owned shared contract; root refreshed shared output and owns the final workspace typecheck. No casting workaround was introduced. Independent review and any user-approved live torch apply remain root gates, not worker claims.
