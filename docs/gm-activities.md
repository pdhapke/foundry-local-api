# Native dnd5e activity activation

`foundry_gm_activity_state` and `foundry_gm_activity_apply` are actual generic MCP and REST descriptors (`POST /api/gm/activities/state`, `/apply`). They dispatch `gmActivitiesRead` and `gmActivitiesApply` through the exact authenticated, opted-in GM bridge, current world and rendered active scene. Transport exposure does not authorize a player or TV client. The reviewed versions are Foundry 14.368 and dnd5e 6.0.3.

The action is `mode: use`, with explicit placed token/actor/item/activity IDs, a bounded unique target list, explicit roll privacy, and a per-target human rules decision. Each decision records its ID, edition (2014 or 2024), range, reach, line of effect, cover and reason. Native activity and target state, resources, revisions and choice options are returned by the read tool. Pass that entire state unchanged as `expectedState`; supply a stable `idempotencyKey` and `correlationId` for apply. Fresh state or fresh IDs never authorize repeating an uncertain spend.

Activation calls native `activity.use` with configuration UI disabled and automatic subsequent actions disabled. Native usage handles item/activity uses, charges/attributes, selected spell slot/upcasting, linked native concentration creation and explicitly chosen concentration replacement. The wrapper never implements a resource arithmetic engine. Consumption defaults come from the actual installed native activity rather than allowing the caller to bypass consumption. Spell slot selection is mandatory where required; scaling must match its native level. Existing concentration never gets an implicit replacement choice.

Attack activities require one exact target and explicit native ability, mode, ammunition and mastery choices when the installed item supplies them. The scaled native activity captured from `dnd5e.postUseActivity` performs an awaited native attack. Native hit evaluation supplies hit/miss; native roll options supply critical/fumble/mode/ability/ammunition metadata. Explicit cover adds only the difference over already prepared native AC cover. Total cover and ambiguous AC overrides fail closed. Range/reach/line of effect remain explicit GM adjudication, not inferred geometry.

Both usage and attack messages must be new persisted messages, correlated to the operation, carry the exact actor/scene speaker and token UUID targets, and acknowledge the requested whisper/blind privacy. An attack also verifies its native origin points to the usage message. Ambient GM target selection is replaced for native processing and restored in `finally`; it never decides tool targeting.

Set optional `damage: true` to await the scaled native activity's `rollDamage` under the same receipt. Attack critical, ability and attack mode come directly from the original native attack roll. Native ammunition document data is captured before attack so ammunition properties and magical bonus survive native deletion of the last ammunition item; damage never spends ammunition a second time. A miss skips damage. The receipt returns bounded native typed components (`value`, `type`, `properties`, formula, critical and native options), correlated damage message IDs and original attack linkage. Multiple unresolved native damage types stop before activation. Target/source binding and positions are checked after each native await; a changed target after consumption remains uncertain and does not authorize an attack or reroll.

Concentration replacement IDs must belong to native maintained concentration effects, not merely an arbitrary actor effect. A new maintained native concentration effect must be present in the activity result and the selected old effect must be absent after use. Native begin/end vetoes become uncertain without reactivation. Disabled native concentration automation requires human workflow.

The private durable native receipt journal reserves before use, records terminal results, and prevents duplicate spending after restart/reconnect. Readback includes slots, item quantities/uses and every activity use; native auto-destroyed source items remain observable in terminal state. Cancellation, hook veto, lost acknowledgement, privacy disagreement or target restoration failure after dispatch is uncertain and must be reconciled without rerolling. Read-only exact-request receipt retrieval remains available when uncertain operations fence new intent.

Started native combat also binds the private persistent combat ledger in expected state. Ordinary action/bonus/reaction use requires an initialized current turn budget; its spend happens under the same outer receipt reservation before native use. Native reactions require an explicit pending interruption linked to the actual activity UUID. The linked interruption resolves with the confirmed activity receipt without spending reaction twice. Uncertain use retains the spent budget for human reconciliation. Native legendary activation consumption remains dnd5e's resource operation.

## Explicit human-required limits

Optional `template: { placements: [{ x, y, direction }], ruling }` selects exact in-scene positions (1-16) and the native activity itself supplies shape, size, width, height and count. The exported installed `dnd5e.canvas.AbilityTemplate.fromActivity` constructs native legacy template geometry. Foundry 14's exported `BaseRegion._migrateMeasuredTemplateData` converts that geometry into the real native Region shape. The adapter persists actual Regions and verifies Region IDs, native shapes, ownership, levels and source flags in `data.placement.templates`; `nativeTemplateData` preserves the native geometry input. It never compares a compatibility projection to persisted Region data. Native strict `dnd5e.utils.convertLength` and an ephemeral source-preserving item clone convert differing scene units. Native grid-aligned cube angle remains native. This exact 6.0.3 legacy factory is deprecated until dnd5e 6.2; it does not provide modern Region behaviors. Attached emanations, rings or applicable Region behavior automation remain an explicit native interactive boundary, rather than claiming saves/effects have completed.

Optional `summon: { profileId, actorId, creatureSize?, creatureType?, placements: [{ x, y, elevation, rotation }], ruling }` uses an existing owned world Actor, matching an actual native profile in native `availableProfiles` after selected scaling; its prototype must be unlinked and non-wildcard. CR profiles accept an explicit existing world NPC selected with the installed native deterministic maximum-CR and type filters. Native `Roll(profile.count)` is evaluated once under the casting reservation, with at most 16 candidate positions; a rolled count exceeding the supplied positions remains uncertain without reroll. Native `getChanges` and `getTokenData` produce actor deltas, effects and item modifiers. Native summon hooks are respected. Source Actor/prototype identity, original ownership and data must remain unchanged at every awaited boundary; permission/link edits, vetoes and partial creations cannot be reported as successful. `data.placement.summons` returns every persisted token ID, native delta and effect IDs. Linked source Actor changes, wildcard file selection and compendium import have security or external side effects outside this bounded operation and require a separate explicit native workflow.

Held spell phases use the same activity tools. `phase: ready, ready: { choiceId, trigger, ruling }` requires an actual one-action spell, started combat and initialized action budget. It casts with native slots/uses exactly once, no outcome targets/attack/damage/placement yet, and explicit concentration begin/replacement. A native ephemeral item clone enables concentration for a normally non-concentration spell without editing the real item. The exact native held effect, real item/activity UUID, original configuration and casting receipt are registered under the same reservation. After an explicit combat ready interruption opens, `phase: release, release: { readyId, castReceipt }` uses the same retained slot/scaling and native source. It verifies confirmed original cast provenance and unchanged source rules, then native use with `consume: false` spends only the linked reaction budget. It can perform explicit current target attack/damage/placement. Normally non-concentration spells remove only the exact held effect afterward; original concentration spells replace the held effect with a native original-duration effect. Lost concentration, changed rules, expired readiness, wrong receipt or native veto refuse or remain uncertain without refunding/recasting. Expiry/end cleanup belongs to the combat ledger. Native applied effects and target saves still require explicit outcome decisions.

Linked activities, non-reviewed activity types and unresolved native choices stop before native usage. Native chat UI remains available for these specific boundaries.

Save activities return native save DC/ability metadata with the activation receipt. This is not proof of a target save. With `damage: true`, damage/healing rolling is complete and the exact components can be applied through the separate typed damage/healing operation. Target saving throws, save multipliers and effect application remain explicit human decisions. The receipt marks this `followUp.humanRequired` and identifies remaining steps; it does not claim compatibility with the separate existing attack ledger. If damage was not selected, later activity-linked rolling uses native chat UI. Never activate or spend the same activity again to perform a follow-up.

## Offline evidence and staged acceptance

Native-shaped tests cover deduplicated native use/attack/damage, critical config forwarding, slot/upcast/uses readback, preserved deleted ammunition data, cancellation and disconnect after spend, stale or changed-during-use target state, exact scope, changed-key payload refusal, auto-destroyed sources, concentration membership and begin/end vetoes, native message privacy/targets/speaker, turn budgets and cover double counting. Endpoint tests exercise strict input schemas, both tool descriptors and denial of player/TV authority with a fake bridge.

Live LAN/browser native activity, privacy, slot/ammo auto-destruction, concentration and multi-client target restoration remain staged deployment acceptance. No live gameplay, installed assets, deployment, provider calls or permission changes were performed by this implementation.
